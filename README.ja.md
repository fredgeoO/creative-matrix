# 格致マトリクス（ゲチ・マトリクス） · Gezhi Matrix

> 格物致知（物を究めて知を致す）。任意の二次元をグリッドに並べ、すべての交差点で「即物窮理（事物に就いてその理を窮む）」を行い、マスごとに一份の推論を生成する。

縦軸と横軸を二次元グリッドに並べる——二つの軸は何にでもなれる：思考モデル、シナリオ制約、人物、タイムライン、卦象……。各交差点をクリックすると、現在のモデルで一份の推論レポートが生成され、ワークスペースの `data/matrix.json` に保存される。

技術上のパッケージ名は依然 `@local/creative-matrix`、ツール id は依然 `creative_matrix`、ルートは依然 `/creative-matrix/api`。変わるのは表示名だけで、移行も再インストールも不要である。

## 名前

**格致** は「格物致知（物を究めて知を致す）」の略である。**格** は掛詞になっていて、マトリクスの中のマス目そのものを指す一方で、「格物」における追究・窮明という動作でもある。**致** は到達を、**知** は認識を意味する。合わせて言えば：マスの中で事物を追究し、それによって認識に到達する、ということである。

このパネルはまさにこの動作を表形式に仕立てたものである。縦軸と横軸は何にでもなれる——縦軸は**物**（思考モデル、概念、日常の品物）であり、横軸は**境**（シナリオ、制約、状況）である。テンプレートを差し替えれば、また別の次元のペアになる。各交差点は一度の「即物窮理（事物に就いてその理を窮む）」——二つの語を貼り合わせるのではなく、ある次元にもう一つの次元の中で推論させ、必然的に生じる帰結を引き出すのである。

もともとの名前は「クリエイティブマトリクス」だった。改名は包装の取り替えではない。「創意」が成果物を記述するのに対し、「格致」は手法を記述する。そしてこのプラグインが本当に希少なものは、後者である。

もう一つ書き留めておくべき細部がある。朱熹は「格物」を、万物の理を外に向かって窮めるもの、マスごとに一格ずつ究めるものとして説いた。王陽明は実際に庭先の竹を究め、七日間究めて病に倒れ、ついに「天下之物本无可格者、其格物之功只在身心上做（天下の物には本来格ぶべきものなく、その格物の功はただ身心の上に做るなり）」と述べた。このマトリクスは朱熹の側に立つ——世界をマスに並べ、一格ずつ推論すれば、いくつかの本物が引き出せると信じている。しかし王陽明のあの問いも記憶しているため、各マスには必ず「どのような場合に失効するか」を書き添え、deep モードではさらに独立したレッドチームを一巡追加する。名前にはその警告が備わっている：格り出したものは美しい推論かもしれないが、真知とは限らない。

## 方法論

### 四ステップ

1. **軸を立てる**：まず縦軸を決める。各行は一つの「物」——思考モデル、メカニズム、日常の品物である。行は具体的で推論可能なものにし、形容詞に書かない。
2. **軸を交差させる**：次に横軸を決める。各列は一つの「境」——シナリオ、制約、状況である。列はそれらの「物」を本当に「突き上げる」ものでなければならない。
3. **理を窮める**：各交差点で生成する。書くのは「メカニズム → 帰結」：この物がこの境の中で、必然的に何が起き、さらにどのような非線形的な帰結が伸びていくか、である。
4. **反証する**：各マスの末尾には必ず一条の「どのような場合に失効するか」を置く。重要なマスは deep モードでレッドチームを一巡追加し、専ら反例を探す。

### なぜ因果推論であり、語の連結ではないのか

「りんご × 朝食のテーブル」が単に「りんごが朝食のテーブルに置かれている」と書かれるだけでは、それは連結であって格致ではない。格致が求めるのは、縦軸を一条の因果律として扱うこと——りんごは酸化し、転がり、儀礼になりうる——であり、それを横軸（朝食のテーブルの時間的プレッシャー、家族関係、早朝の注意力）の中で必然的に帰結を生じさせることである。成果物は反論可能な一段の推論であって、耳障りの良い連想の一文ではないべきである。

### やらないこと

- 卜筮の約束はしない。易経テンプレートは六十四卦を思考の道具として扱うだけで、吉凶を予測しない。
- 「学際」を飾りにしない。各マスは必ず答えられなければならない：この次元はここで結局どの判断を変えたのか、と。
- 単一マスの「豁然贯通」を追い求めない。貫通は很久後に振り返って見えてくるもので、一つのマスが与えられるものではない。

## 引用

名前と方法論はいくつかの出典に基づく。文言を改める際は併せて確認されたい：

1. 『礼記・大学』：「致知在格物（知を致すは格物に在り）。」「物格而后知至（物格ったるのち知至る）。」
   *『礼記・大学』のこの二句は、認識に到達するのは事物を究めることにあり、事物が窮められてはじめて認識が至る、と説いている。*
2. 朱熹『四書章句集注・大学章句』の格物致知伝の補い：「所谓致知在格物者、言欲致吾之知、在即物而穷其理也（いわゆる知を致すは格物に在りとは、我が知を致さんと欲するは、即物にしてその理を窮むるに在ると言うなり）。」また：「至于用力之久、而一旦豁然贯通焉（用力の久しきに至りて、一旦豁然として贯通する有り）。」
   *朱熹は、認識に到達するのは事物に就いてその理を窮めることにあると説く。力を尽くして久的に究めれば、ある瞬間ひらめて豁然と贯通する、という。*
3. 王陽明『伝習録』下巻（黄以方録）：庭先の竹を究め、「天下之物本无可格者、其格物之功只在身心上做（天下の物には本来格ぶべきものなく、その格物の功はただ身心の上に做るなり）」。
   *王陽明は実際に竹を究めようとして失敗し、万物を外に究めるのではなく、格物の功はただ自らの身心の上で行うべきだと結論づけた。*
4. 晩清に「格致」をもって science を訳し、傅蘭雅が主編した『格致彙編』（1876、上海）。「格致学」とは当時の自然科学を指した。

> 第 4 条は「格致」という語の近代的用法を説明するだけで、本プラグインが科学的方法と等しいことを意味しない。

## 機能

- **縦軸 / 横軸**：既定はりんご、水、影 × 朝食のテーブル、雨の日、遊園地といった日常概念。ヘッダーはタイトルと概要を表示し、タイトルをクリックして改名、概要をクリックして編集でき、概要もプロンプトに入る。軸の追加・削除もすべてヘッダーで行う。
- **三つのビュー**：ページヘッダーの下に「テンプレート / マトリクス / プロンプト」の三つのタブがあり、既定でテンプレートを開く。選んで読み込むと自動的にマトリクスへ遷移する。マトリクスタブではテーマ、軸名、軸概要、軸の増削を変更でき、テンプレートとプロンプトはもうポップアップせず、切り替えればそのまま全ページワークスペースになる。現在のタブのみがマウントされ、離れる際に未保存の下書きは破棄される。
- **ページヘッダーのコントロール**：右側に順に、**モデル**ドロップダウン（DSH が到達できるすべての provider / model を列挙。ローカルの NInfer、Strata を含む。各マトリクスは自分のモデルを記憶し、「既定モデルに従う」を選ぶと DSH の既定選択に戻る）、**並行度**ドロップダウン（0 = 一括、または 1/2/3/4/6/8/12）、**テンプレート保存**ボタン、**更新**と ⋯ メニュー（Markdown エクスポート、「一括生成…」ポップアップ。ポップアップ内でも空マスだけを生成するかにチェックでき、既定でチェック済み）。
- **テーマは左上隅**：グリッドの左上マスはこのマトリクスのテーマを表示し、クリックしてその場で編集する（Enter / 焦点喪失で保存、Esc でキャンセル）。テーマの下に「生成済みマスを含む」チェックボックスと、マトリクス全体の「全生成」ボタンがある：塗りつぶしのブランドカラーで、既定は空マスだけを補う。チェックするとボタンは「すべて再生成」に変わり、全マスをやり直して既存の内容を上書きする。一括実行中は同じボタンが「生成中 x/y · 停止」になる。
- **各軸に専用の生成ボタン**：各行/列のヘッダーに「▷ 生成」と「全」チェックボックスが付く。既定ではこの軸上の空セルだけを生成し、「全」にチェックすると軸全体を再生成する。隣の「×」は二度押しで確認となり、軸を削除できる（最低 1 行 1 列を残す）。
- **マス数はいつでも変更可能**：ヘッダー右の「+ 横軸を追加」、表の下部の「+ 縦軸を追加」で直接追加。任意の行/列を削除するとマトリクスは即座に新しいサイズになり、最小 1×1 まで対応する。
- **プロンプトをカスタマイズ可能**：「プロンプト」タブで**システムプロンプト**と**ユーザメッセージ**の二つのテンプレートを別々に編集し、**開くと現在有効なテンプレートの全文を表示する**（変更していなければ内蔵既定）。両方に `{縦タイトル}`（`{row}`）、`{横タイトル}`（`{col}`）、`{テーマ}`（`{theme}`）などのプレースホルダを書け、モデル呼び出し前に現在のセル内容で置換される。右側には全プレースホルダと意味・例示値を列挙し、実際に送信される system / user の二通のメッセージをリアルタイムでプレビューする。触れずにそのまま保存 = 内蔵既定に従い続ける。二つのプロンプトはマトリクスとともに保存され、テンプレートとともに存取される。
- **テンプレート**：内蔵 7 種——身の回りの小さな創意、未来研判、グリッド理論（latticework）、物語創作、人生計画、易経卦象、禅の道理。各セットに説明と使い方を備え、**各セットが自分専用の生成プロンプトを一文持つ**（統一句式「……直接この一段を書き、前置きは不要。」で、テンプレートを読み込むと切り替わる）。
- **テンプレートをプロンプトで生成 / 書き換え**：「テンプレート」タブに「テンプレート読み込み / プロンプトで生成」の二つのサブタブがある。「プロンプトで生成」は欲しいマトリクスを一文で説明し、モデルが下書き（二軸 + テーマ + プロンプト）を出力、確認後にプリセットとして保存する。「マイ」プリセットの詳細ページには「プロンプトで修正」があり、何を直すか書けばその場でファイルを改写する。Agent 側は `creative_matrix(action:'template', idea, save?, file?, refineFile?)` に対応する。
- **テンプレート保存**：ページヘッダーの「テンプレート保存」は現在の縦軸/横軸/テーマ/プロンプトを `presets/*.md` に書き出す。ダイアログでは**現在のテンプレートに上書き**（ユーザテンプレートのみに可）または**新規テンプレートとして保存**を選べる。ファイルは通常の Markdown で、手編集も git 管理もできる。テンプレートはタイトル、軸、プロンプトだけを保存し、生成されたマスは保存しない。
- **テンプレート削除**：テンプレートタブで自分のテンプレートを選ぶと、詳細に赤い「テンプレート削除」ボタンが一つある：一度目のクリックで「削除を確認」に変わり、二度目で実際に削除する。内蔵テンプレートは読み取り専用で、ボタンは無効化され理由が示される。削除は `presets/*.md` を消すだけで、現在のマトリクスと生成済みマスに影響しない。もし現在紐づいているテンプレートを削除した場合は、同時に紐づけも解除される。
- **一括生成**：表の左上隅の「全生成」でマトリクス全体を実行。単一行/単一列は各軸自身の生成ボタンを使う。すべての一括ボタンは既定で空マスだけを補い、「生成済みマスを含む / 全」にチェックして初めて既存の内容をやり直す。既定は一括（全部並列）で、ページヘッダーの「並行度」を 1/2/3/4/6/8/12 に変更でき、いつでも停止可能。マトリクス上部に進捗と失敗カウントが表示される。
- **セル**：縦軸を因果律として扱い、それが横軸シナリオの中で必然的に生む非線形的帰結を推論する。末尾に一条の「どのような場合に失効するか」を添える。
- **深いレビュー**：下書き完成後に独立したレッドチームを一巡追加し、「独立レッドチームレビュー」を追記する。
- **Agent ツール**：`creative_matrix`。任意の会話でマトリクスを読み、セルを生成/書き込み、モデルを切り替えられる。
- **自動保存**：生成/編集のたびに `data/matrix.json` に書き戻す。書き込みに失敗するとマトリクス上部に非永続化の警告が出る。

| `locale/{en,zh}.json` | プラグイン管理ページのタイトル/説明 |

データは既定で次に書き込まれる：

```
<baseDir>/data/matrix.json       # 現在のマトリクスと生成結果
<baseDir>/presets/*.md           # ユーザが保存した軸プリセット
```

`baseDir` の既定は patch 内の `polymath_matrix` ワークスペース。マトリクスファイルは通常の JSON で、直接読め、git 管理でき、Agent の fs ツールで読み取れる。`reset` は旧ファイルを `matrix.json.bak-<ts>` にリネームするだけで、黙って削除することはない。

制限：行/列は各 1〜12。name ≤ 80 文字、hint ≤ 300、theme ≤ 500、prompt / userPrompt ≤ 4000。単一 cell の markdown ≤ 200 KB。ファイル ≤ 8 MB。同一軸内の名前の重複は不可。読み取り時に正規化され、存在しない軸を指す cell は破棄され `warning` に報告される。

ディスク書き込みは `tmp + rename` で、同一ランタイム内は逐次実行。外部でファイルが変更されると、次の `state` で mtime に従って再読み込みする。

## テンプレートとプリセット

内蔵テンプレートは `templates/`、ユーザプリセットは `presets/` に書き込まれる。両者は Markdown + 短い frontmatter の形式：

```md
---
title: 身の回りの小さな創意            # 身边的小创意
description: 身の回りの事物 × 日常シナリオで、二つのありふれた概念をぶつけて新しい点子を生む練習。   # 身边事物 × 日常场景，练习把两个普通概念撞出新点子。
theme: 身の回りの事物の組合せの変化を示す。   # 体现身边事物的组合变化。
prompt: |
  身近なもので型破りな点子を出し、各アイデアになぜかを言えるようにする。直接この一段を書き、前置きは不要。   # 用身边的东西想出不寻常的点子，每个想法都要能说出为什么。直接写这一段，不要开场白。
rows:
  - name: りんご            # 苹果
    hint: ありふれた果物。見られ、食べられ、変色し、腐る   # 一种普通水果，能看、能吃、会变色、会腐烂
  - name: 水            # 水
    hint: 流れ、凍り、蒸発し、ものをふやかせる   # 会流动、会结冰、会蒸发，也会把东西泡软

  - name: 朝食のテーブル            # 早餐桌
    hint: 毎朝起こる小さなシナリオ。時間が非常にタイト   # 每天早上都会发生的小场景，时间很紧
  - name: 雨の日            # 下雨天
    hint: 計画は乱れるが、新しい遊びも生まれる   # 计划被打乱，但也能玩出新花样

```

- **テンプレートが何を保存するか**：タイトル、説明、テーマ、縦横軸のタイトル（hint を含む）、**システムプロンプト**、**ユーザメッセージテンプレート**。**生成されたマスの中身は一切保存しない**。
- `prompt` は**一行一文**で書き、生成時にモデルへ渡す system プロンプトそのもの。書かなければ内蔵既定の一文を使う。`{縦タイトル}`（`{row}`）、`{テーマ}`（`{theme}`）などのプレースホルダを含められる（「生成プロンプト」節を参照）。保存されるのは依然テンプレートである。複数行も読めるが、一文のほうが使いやすい——長さはこの文に書いた字数で制御する。内蔵 7 種はいずれも「……直接この一段を書き、前置きは不要。」という句式で統一している。
- `userPrompt` はユーザメッセージテンプレートを書く（同様にプレースホルダに対応、通常は複数行）。書かなければ内蔵既定を使う。一行内のプレースホルダがすべて空のときはその行ごと省略し、空の「（）」も除去される。
- 内蔵テンプレートは読み取り専用。「テンプレート保存」は `presets/` にのみ書き、または自分のユーザテンプレートに上書きする。
- テンプレートを読み込むと、その rows/cols/theme/prompt/userPrompt で現在のマトリクスを置換する。旧 cell は旧軸とともに置換され、パネルは再確認のうえ何マス消えるかを表示する。
- **テンプレート保存**：ページヘッダー「テンプレート保存」→「現在のテンプレートに上書き」（マトリクスがユーザテンプレート由来の場合のみ）または「新規テンプレートとして保存」。現在の theme、rows/cols、二つのプロンプトを書き込む。説明と本文も併せて編集できる。新規で同名がある場合は自動的に `-2`、`-3` が付き、黙って上書きすることはない。
- **テンプレート削除**：テンプレートタブ → 自分のテンプレートを選択 → 詳細の赤い「テンプレート削除」→ もう一度「削除を確認」。`presets/*.md` を消すだけで、現在のマトリクスとマスは変わらない。現在紐づくテンプレートを削除した場合、`data/matrix.json` の `preset` はクリアされ、ページヘッダーは「テンプレート未紐づけ」に戻る。内蔵テンプレートは読み取り専用で、削除ボタンは無効。
- `data/matrix.json` は `preset: {file,title,source}` を記録するため、パネルを開き直しても「上書き」がどのファイルに書くべきかを覚えている。
- ファイル内の `description`、二つのプロンプト、本文はすべてテンプレート詳細ページに表示される。

### プロンプトでテンプレートを生成・修正する

frontmatter を手書きしたくないときは、モデルに書かせる：

- **新規作成**：テンプレートタブ →「プロンプトで生成」サブタブ → 欲しいマトリクスを説明（テーマ、二軸、スタイル）→「起草」。モデルは下書き一份（タイトル、説明、テーマ、縦横軸各 4〜8 項目、生成プロンプト一文）を返し、下にプレビューを列挙。満足なら「プリセットとして保存」で `presets/` に書き込み、以後他のテンプレートと同じように読み込める。
- **修正**：「マイ」でユーザプリセットを選択 → 詳細の「プロンプトで修正」→ 何を直すか書く（例「横軸をリモートワークシナリオに換える」「口調をもっと辛くする」）→「起草」でそのファイルをその場で改写。本文の説明とファイル名はそのまま保たれる。モデルが書き漏らしたフィールドは現在のマトリクスまたは既存値に戻り、カスタムプロンプトを黙って既定に格下げすることはない。
- **内蔵テンプレートは読み取り専用**：内蔵テンプレートを直したい場合は、まず読み込み、ページヘッダーの「テンプレート保存 → 新規テンプレートとして保存」で自分のプリセットとして保存し、それからプロンプトで直す。
- 起草/改写にはこのマトリクスで現在有効なモデルを使う（パネルで切替可）。1 回の呼び出しで出力予算は約 1600 token。

対応 API：`presets.draft`（`{idea}` → `{draft,model,raw}`）、`presets.refine`（`{id,idea}` → 元ファイルに書き戻し、新しい `preset` を返す）。

## 生成プロンプト

各セルは二つのプロンプトを変更できる：**システムプロンプト**（通常一文）と**ユーザメッセージテンプレート**（通常複数行）。二つの編集ボックスに保存されるのは**テンプレート**で、最終テキストではない。プレースホルダはモデル呼び出しのたびに、現在のセル内容で置換される。

| プレースホルダ | 別名 | 意味 |
|---|---|---|
| `{縦タイトル}` | `{row}` | 縦軸タイトル（思考モデル名） |
| `{縦ヒント}` | `{rowHint}` | 縦軸 hint |
| `{横タイトル}` | `{col}` | 横軸タイトル（シナリオ名） |
| `{横ヒント}` | `{colHint}` | 横軸 hint |
| `{テーマ}` | `{theme}` | このマトリクスのグローバルテーマ |
| `{テンプレート名}` | `{title}` | マトリクスタイトル（テンプレート由来または既定タイトル） |
| `{補足要求}` | `{hint}` | 今回の生成における追加要求（セルドロワー内の hint。一括生成時は空） |
| `{前バージョン}` | `{previous}` | このマスの前バージョンの一文結論 |
| `{座標}` | `{cell}` | `縦タイトル × 横タイトル` |

ルール：

- 中国語プレースホルダは完全一致で照合。ASCII 別名は大文字小文字を区別しない（`{ROW}` は `{row}` と同値）。
- 認識できない `{…}` は**そのまま保持**し、JSON・LaTeX などの通常の中括弧を誤って壊さないようにする。値が空のときは空文字列に置換される。
- ユーザメッセージテンプレートは行単位で処理する。一行内のプレースホルダが**すべて空**のときはその行ごと省略し、空の「（）」も除去する。これにより `テーマ：{テーマ}` はテーマが無いときに空ラベルを残さない。
- 置換は送信前にのみ発生する。`data/matrix.json` と `presets/*.md` に保存されるのは常にプレースホルダ付きのテンプレートで、軸一式を差し替えてもそのまま使える。
- 「プロンプト」タブの右側に全プレースホルダを列挙し、クリックすると**最後に編集したボックス**（システムまたはユーザ）に挿入され、プレビューセルでの実際の値を表示する。下に実際に送信される **system** と **user** の二通をリアルタイムでプレビューする（サブエージェント/チャット内の「プロンプトをコピー」も同じ置換経路を通る）。
- 両方とも「開くと現在有効な全文」に従う：カスタムが無ければ内蔵既定を表示。触れずにそのまま保存 = 内蔵既定に従い続け、既定テキストをコピーとして凍結しない。「内蔵既定に戻す」で両ボックスにワンクリックで復帰する。
- プロンプトの保存は `data/matrix.json` の `prompt` と `userPrompt` の両方に書き込む。以後すべての生成（単一マス、各軸の一括、Agent ツール）はこの二つを使う。テンプレートを読み込むと二つまとめて差し替わる。テンプレートに `userPrompt` が無ければ内蔵既定に戻る。
- 内蔵既定のシステムプロンプトは一文のみ：「縦横軸を踏まえ、150 字未満で、このモデルがこのシナリオで何を逼り出したかを明らかにする。」（結合纵横轴，用少于 150 字说清这个模型在这个场景里逼出了什么。）既定のユーザメッセージテンプレートは「縦軸（モデル）：{縦タイトル}（{縦ヒント}）/ 横軸（シナリオ）：{横タイトル}（{横ヒント}）/ テーマ：{テーマ} / 補足要求：{補足要求} / 前バージョンの結論（重複しないこと）：{前バージョン} / 直接この一段を書き、前置きは不要。」で、空行は自動的に省略される。

## 一括生成

各行 / 列のヘッダーに生成ボタンがあり、ページヘッダーで先に軸を選ぶ必要はない：

- **ヘッダー「▷ 生成」**：既定ではその行（縦軸項目）またはその列（横軸項目）上のすべての空セルを生成。すでに内容のあるマスは自動的にスキップ。空セルが無い場合は黙ってやり直さず、「全」にチェックするよう促す。
- **ヘッダー「全」チェックボックス**：チェックすると同じボタンが「▷ 再生成」に変わり、軸全体の全マスをやり直して既存の内容を上書きする。チェックしなければ空だけを補う。
- **左上隅「全生成」**：既定でマトリクス全体の空を埋める。ボタンの上の「生成済みマスを含む」にチェックすると、ボタンは「すべて再生成」に変わりマトリクス全体をやり直し、色もブランドカラーから警告色に変わる。
- **⋯ →「一括生成…」**：一括ポップアップを開き、既定で「空セルのみ生成」にチェック。チェックを外して初めてその範囲内の既存内容を上書きする。

一括開始後：

- **既定は一括**：1 回の一括ですべての対象マスを同時に生成開始。ページヘッダーの「並行度」ドロップダウンで 1/2/3/4/6/8/12 を選んで同時進行のマス数を制限できる（0 = 一括）。
- 各 cell が完了するたびにディスクに書き込み、グリッドを更新。並行度は一括開始時に固定され、実行中はドロップダウンが無効になる。
- マトリクス上部に進捗バー、ページヘッダーに進捗 chip が現れ、同時進行マス数、成功/失敗/スキップカウントを含む。
- いつでも「一括を停止」できる。停止は進行中の全マスを中断し、完了済みは保持される。
- 一括の途中でページを更新しても進捗は失われない：`state.batch` が報告を続け、パネルがポーリングで復旧する。
- マスが失敗してもバッチ全体は中断されず、失敗理由が進捗バーの下に列挙され、個別に再試行できる。

対応 API：`batch.generate`（SSE または JSON の最終結果、`concurrency` を付けられる）、`batch.cancel`、`batch.clear`。SSE イベントは `batch.start`、`cell.start`、`cell.done`、`cell.error`、`batch.done`。

## 軸の増削・改名と概要

- ヘッダーのタイトルをクリック → その場で改名（Enter で保存、Esc でキャンセル）。
- タイトル下の概要をクリック → その場で編集（Enter で保存、Esc でキャンセル、焦点喪失で保存）。概要はシステムプロンプトとユーザメッセージテンプレートの `{縦ヒント}` / `{横ヒント}` に入り、テンプレート詳細にも表示される。
- 表の最も右の列ヘッダー「+ 横軸を追加」、最後の行の「+ 縦軸を追加」→ 名前を入力して Enter で軸を一本直接追加。
- ヘッダーの「×」→ 一度目で赤に点灯（「もう一度押すと削除」）、二度目で実際に軸を削除。軸削除はその軸上のセルをカスケード削除する。各軸は最低 1 項目を残し、最小マトリクスは 1×1。
- これらの編集はすべて「マトリクス」タブ内で完結し、即座に `data/matrix.json` に書き戻す。専用の次元編集ページはもう不要。

## HTTP API

プレフィックスは `/creative-matrix/api`、同一オリジン（ループバック + Origin/Host 一致）でのみ利用可能。

| method | 説明 |
|---|---|
| `GET /creative-matrix/api` | `state` と同等 |
| `state` | 軸、テーマ、cell 要約、有効モデル、`selectedModel`、`concurrency`、`batch` 進捗、`persisted`、`storePath`、`generating`、warning、`storeError` |
| `models.list` | DSH が到達できる provider とモデルを列挙。`{refresh:true}` で 60 s キャッシュを回避 |
| `model.set` | `{provider,model}` をマトリクスのモデルに書き込む。両方空欄 = 既定に従う |
| `concurrency.set` | `{concurrency}` で同時生成するマス数を設定。`0` = 一括（無制限） |
| `cell.read` / `cell.write` / `cell.clear` | セルの読み書き/クリア |
| `cell.generate` | 生成。`Accept: text/event-stream` なら SSE、そうでなければ JSON の最終結果を待つ |
| `cell.cancel` | この cell の生成を中断 |
| `batch.generate` | 一括生成。`{scope:'all'|'row'|'col', rowId?, colId?, onlyEmpty?, mode?, concurrency?}`。SSE または JSON |
| `batch.cancel` | 実行中の一括を停止（生成中の全マスを中断） |
| `batch.clear` | 完了済みの一括サマリーを折りたたむ |
| `axes.replace` | 軸を丸ごと置換（ヘッダー「×」で軸削除、テーマ保存）：軸削除は cell をカスケード削除 |
| `axes.upsert` | 増改のみ、削除なし（Agent ツールとヘッダー「+ 軸を追加」）：id または名前で照合 |
| `axes.update` | ヘッダー内インライン編集：`{axis:'row'|'col', id, name?, hint?}`。変更するフィールドのみ渡す |
| `prompt.set` | `{prompt,userPrompt}` を本マトリクスのシステムプロンプトとユーザメッセージテンプレートに書き込む。省略したフィールドは元値を保持、空文字列 = 内蔵既定 |
| `prompt.default` | 現在言語の `{system,user}` の二つの内蔵既定テンプレートを返す |
| `presets.list` / `presets.read` | 内蔵テンプレートとユーザプリセットの列挙/読み取り |
| `presets.save` | 現在の theme/rows/cols/prompt/userPrompt を `presets/<title>.md` に保存。`file` + `overwrite:true` でユーザテンプレートに上書き可、`bind:true` でマトリクスをそのテンプレートに紐づけ |
| `presets.draft` | プロンプトでテンプレートを起草：`{idea}` → `{draft,model,raw}`。ディスク書き込みなし |
| `presets.refine` | プロンプトでユーザプリセットを改写：`{id,idea}`、元ファイルに書き戻す。内蔵テンプレートは `BUILTIN_PRESET` を返す |
| `presets.delete` | ユーザプリセットを削除 |
| `presets.apply` | テンプレートを現在のマトリクスに適用し、`removedCells` を返す |
| `prompt.preview` | あるマスが最終的に送信する二通をプレビュー：`{rowId,colId,hint?,custom?,userCustom?}` → `{template,userTemplate,system,user,vars}`。二つの `custom` はまだ保存されていないシステム / ユーザの下書きをそれぞれプレビュー |
| `export.markdown` | マトリクス全体を Markdown に組む |
| `reload` | ファイルの強制再読み込み |
| `reset` | 既存ファイルを `.bak-<ts>` にリネーム後、サンプルマトリクスを再構築 |

リクエストボディ：`{"method":"cell.generate","args":{...}}`。成功は `{"ok":true,"value":...}`、失敗は `{"ok":false,"error":"...","code":"..."}`。

SSE イベント：

```
event: meta    data: {"provider":"…","model":"…"}
event: stage   data: {"stage":"draft"|"critique"}
event: delta   data: {"text":"…"}
event: done    data: {"key":"r-…:c-…","cell":{…},"persisted":true}
event: error   data: {"code":"…","message":"…"}
```

単一実行（single-flight）：同一 cell をもう一度生成すると旧リクエストを abort する（latest wins）。手動リクエストは `concurrency.set` の上限の制約を受け、既定 0 = 無制限。上限超過のリクエストはキューに入り、30 s 以内に回ってこない場合は `429` を返す。一括生成は自前の並行プールを持ち、実行中に単一マスリクエストに押し出されることはない。クライアント切断は生成を中断せず、完了すれば通常どおりディスクに書き込まれる。ページ更新後も `state.generating` に見えるまま残る。

## Agent ツール

```
creative_matrix(
  action: 'state' | 'read' | 'generate' | 'write' | 'clear' | 'axes' | 'model' | 'template',
  rowId?, colId?, hint?, mode?: 'fast'|'deep',
  markdown?, theme?, prompt?, userPrompt?, rows?: [{id?,name,hint?}], cols?: [{id?,name,hint?}],
  provider?, model?, idea?, save?, file?, refineFile?
)
```

- `state` は軸 id/名称/ヒント、テーマ、二つのプロンプトの状態、cell 要約と有効モデルを返す。全文は返さない。
- `read` は単一 cell の全文を返す（8000 文字超は切り詰め）。
- `generate` はパネルと同じランタイムを共有し、既定で保存する。
- `axes` は増改のみで削除しない。`prompt`（システムプロンプト）と `userPrompt`（ユーザメッセージテンプレート）を併せて書ける。軸削除はパネル内でのみ可能。
- `model` はこのマトリクスのモデルを切り替える。`provider` と `model` を一緒に空欄にすれば既定に従う。
- `template` はプロンプトでテンプレートを起草する。`idea` は必須で、下書きを返す（ディスク書き込みなし）。`save: true` で直接 `presets/*.md` として保存（`file` でファイル名を指定可）。`refineFile` はあるユーザプリセットを指名して改写し、そのファイルに書き戻す。

## 設定

```yaml
- insert:
    - id: creative-matrix
      name: '@local/creative-matrix'
      config:
        baseDir: 'C:\Users\zgw31\Documents\deepseek-harness\polymath_matrix'
        maxTokens: 500         # 一格約 150 字、500 は単なる余裕分で、長さ制御器ではない（一格约 150 字，500 只是余量，不是长度控制器）
        critiqueMaxTokens: 200
        temperature: 0.85
        outputLanguage: zh      # zh | en
        concurrency: 0          # 0 = 一括（全部同時生成）。1〜32 も可（0 = 一次过，全部同时生成；也可填 1–32）
```

`cordis.patch.yml` に実際に設定されているのは上の六項目のみ。ランタイムはこれらの省略可能項目もサポートする（書かなければ既定値）：

| 設定 | 既定 | 説明 |
|---|---|---|
| `reasoningEffort` | `''` | `''` = モデルが対応する最低推理ランク。`'selection'` = 既定選択を踏襲。具体的な id も書ける |
| `storePath` | `data/matrix.json` | `baseDir` 相対または絶対パス |
| `presetsDir` | `presets` | `baseDir` 相対または絶対パス |
| `provider` / `model` | 空 | 既定モデルを上書き（パネル選択がここより優先） |
| `timeoutMs` | 180000 | 単一のモデル呼び出しのタイムアウト |
| `queueTimeoutMs` | 30000 | キュー待ちリクエストの待機上限、超過で 429 を返す |

`concurrency` は起動値にすぎない。パネル上部の「並行度」ドロップダウンでランタイムに変更でき（`concurrency.set`）、変更は次バッチから即座に反映され、Host 再起動後は設定値に戻る。

モデル解決順序：`config.provider` + `config.model` → マトリクスに保存された `model` → `ctx.agentDefaultModel.currentSelection()`。いずれも無い場合パネルは `NO_MODEL` を表示し、モデルを勝手に選んだりしない。

推理ランクの既定は「モデルが対応する最低ランク」を取る：創意的推論では出力予算を本文に残す必要があり、推論過程に全 token を食わせたくはない。より深い思考が必要なら `reasoningEffort` を `'selection'` か具体的な effort id に設定し、`maxTokens` を相应に引き上げる。

## 設計説明

- **UI とデータの分離**：`client.js` には store、SSE、Host API アクション、スロット登録だけを残す。`client.ui.js` は遅延読み込みされる React 側で、コンポーネント・Markdown レンダリング・CSS のみを担当する。両者の間には一つの `deps` facade（状態読み取り + アクション + パネルマウントのライフサイクル）しかなく、UI は `fetch` や store 内部に直接触れない。今後の UI 再編は `client.ui.js` のみを変更する。
- **三タブワークスペース**：テンプレート / マトリクス / プロンプトを各タブに割り当て、既定でテンプレートを開く。現在のタブのみがマウントされ、離れる際に未保存の下書きは破棄される。マトリクスタブ内のテーマ、軸名、軸概要、軸の増削はいずれも即時保存で、「適用」というステップは無い。モデルと並行度の選択はページヘッダー右に置く（グリッド下に隠さない）。これらはマトリクス全体のグローバル設定だからである。
- **マトリクス編集とテンプレート書き込みを分離**：ヘッダー編集（改名、概要、軸の増削）、テーマ、二つのプロンプトは `data/matrix.json` にのみ書く。「テンプレート保存」だけが `presets/` に書き、一字直すたびにテンプレートファイルが増えるのを避ける。
- **メインパネルであってチャット内インラインではない**：グリッドは横方向の空間が必要で、生成はセッションを汚すべきではない。
- **システムプロンプトは一文のみ**：既定は「縦横軸を踏まえ、150 字未満で、このモデルがこのシナリオで何を逼り出したかを明らかにする。」（結合纵横轴，用少于 150 字说清这个模型在这个场景里逼出了什么。）の一文のみ。6 条のハードルール + 例でフォーマットを制御してみたが、結果は各マスが安定して 2000 字・五つの小見出しを出力した。一文に替え字数を文の中に書き込むと、同じモデルなのに安定して 90〜150 字に収まった。変えたければパネル内で変更し、マトリクスとテンプレートとともに保存されるため、コードを変える必要はない。
- **ユーザメッセージも編集可能だが、既定構造は不変**：既定のユーザテンプレートは、かつて手書きした「縦軸 / 横軸 / テーマ / 補足要求 / 前バージョン / 直接書く」の構造を再現している。空値の行は省略し空括弧は除去するため、既定出力は旧版と一致する。項目を増えたければユーザテンプレートに追記すればよく、コードを変える必要はない。
- **プロンプトはテンプレートで、置換は送信前**：二つの編集ボックスと `presets/*.md` に保存されるのはプレースホルダ付きの原文。`lib/prompt.js` は生成・一括・プロンプトコピー・パネルプレビューのたびに、同じ一套の `promptVars` / `renderPrompt` で現在のマスに従って置換する。未知の `{…}` はそのまま保持し、JSON/LaTeX を誤って壊さない。パネルは Host が返す `vars` を表示するだけで、別の置換ロジックを書き足さない。
- **一括のスコープは既定で空だけを補う**：左上隅と各軸のチェックボックスは既定でオフ、これは「空だけを補う」に等しい。チェックして初めてそのスコープを再生成し既存内容を上書きする。空の無い軸には「全」にチェックするよう明示的に促し、「もう一度押す」という隠れ状態で上書きを発動する方法は取らない。
- **JSON ではなく Markdown**：SSE ストリーミングが自然で、JSON 修復のリトライを避けられる。マスラベル（takeaway）は本文の頭文を取り、長すぎる場合は句読点で切るだけで、60 字を機械的に切ることはない。旧形式の `> 一句话：` 行は依然優先して認識する。
- **Host 側生成**：パネルと Agent ツールは `lib/core.js` を共有し、二種の呼び出しがそれぞれ別のロジックを書くことはない。
- **テンプレートは Markdown ファイル**：人間可読で手編集でき、バージョン管理できる。内蔵とユーザプリセットは同じ一套のパーサを使う。
- **iframe は使わない**：メインパネル内で React を直接レンダリングし、テーマ token と locale を継承する。
- **安全なレンダリング**：自作の Markdown サブセットで、すべて React のテキストノード。`dangerouslySetInnerHTML` は使わない。

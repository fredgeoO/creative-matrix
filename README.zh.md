# 格致矩阵 · Gezhi Matrix

> 格物致知。把任意两个维度排成一张网格，在每一个交叉点上「即物穷理」，逐格生成一份推演。

把纵横两轴排成二维网格——两轴可以是任何东西：思维模型、场景约束、人物、时间线、卦象……在每个交叉点点一下，用当前模型生成一份推演报告，保存在工作区的 `data/matrix.json` 里。

技术包名仍是 `@local/creative-matrix`，工具 id 仍是 `creative_matrix`，路由仍是 `/creative-matrix/api`；只有显示名改了，不需要迁移或重装。

## 名字

**格致**是「格物致知」的缩写。**格**是双关：既是矩阵里一格一格的格子，也是「格物」里推究、穷究的动作；**致**是抵达，**知**是认知。合起来：在格子里推究事物，从而抵达认知。

这张面板正好把这个动作做成了一张表：纵横两轴可以是任何东西——纵轴是**物**（思维模型、概念、日常物件），横轴是**境**（场景、约束、处境），换一个模板就是另一对维度；每一个交叉点就是一次「即物穷理」——不是把两个词拼在一起，而是让一个维度在另一个维度里推演出它必然产生的后果。

它原来的名字是「创意矩阵」。改名不是换包装：「创意」描述的是产出，「格致」描述的是方法；而这个插件真正稀缺的东西，是后者。

还有一个细节值得记下来。朱熹把「格物」讲成向外穷尽万物之理，一格一格地格；王阳明真去格亭前的竹子，格了七天，病倒，最后说「天下之物本无可格者，其格物之功只在身心上做」。这张矩阵站在朱熹那一边——它相信把世界排进格子、逐格推演，能逼出一些真东西；但它也记得王阳明那一问，所以每一格都必须写「什么情况下会失效」，深度模式还要再跑一轮独立红队。名字里自带它的警告：格出来的可能是漂亮的推演，不一定是真知。

## 方法论

### 四步

1. **立格**：先定纵轴。每一行是一个「物」——一个思维模型、一个机制、一个日常物件。行要具体、可推演，不要写成形容词。
2. **交错**：再定横轴。每一列是一个「境」——一个场景、一条约束、一种处境。列要真的会「顶」到那些物。
3. **穷理**：在每个交叉点生成。写的是「机制 → 后果」：这个物在这个境里，会必然发生什么，又会长出什么非线性后果。
4. **验伪**：每格结尾必须有一条「什么情况下会失效」；重要格子用 deep 模式再跑一轮红队，专门找反例。

### 为什么是因果推演，不是词语拼接

「苹果 × 早餐桌」如果只写成「苹果放在早餐桌上」，那是拼接，不是格致。格致要求：把纵轴当作一条因果律（苹果会氧化、会滚、会成为仪式），让它在横轴（早餐桌的时间压力、家庭关系、清晨的注意力）里必然地产生后果。产物应该是一段可以反驳的推理，而不是一句好听的联想。

### 不做的事

- 不做占卜承诺。易经模板只把六十四卦当作思维工具，不预测吉凶。
- 不把「跨学科」当装饰。每个格子必须能回答：这个维度在这里究竟改变了什么判断？
- 不追求单格「豁然贯通」。贯通是很久以后回头看见的，不是一格能给的。

## 图标

`icon.svg` 是一张九宫格，中间一格亮起：格是方法，亮是那一格被穷尽之后的结果。

## 引用

名字与方法出自这几处，改文案时请一并核对：

1. 《礼记·大学》：「致知在格物。」「物格而后知至。」
2. 朱熹《四书章句集注·大学章句》补格物致知传：「所谓致知在格物者，言欲致吾之知，在即物而穷其理也。」又：「至于用力之久，而一旦豁然贯通焉。」
3. 王阳明《传习录》下卷（黄以方录）：亭前格竹，「天下之物本无可格者，其格物之功只在身心上做。」
4. 晚清以「格致」译 science，傅兰雅主编《格致汇编》（1876，上海）；「格致学」即当时的自然科学。

> 第 4 条只解释「格致」一词在近代的用法，不表示本插件等同于科学方法。

## 功能

- **纵轴 / 横轴**：默认是苹果、水、影子 × 早餐桌、下雨天、游乐场这类日常概念；表头显示标题和简介，点标题改名、点简介编辑，简介也会进入提示词。加轴、删轴也都在表头完成。
- **三个视图**：页头下方是「模板 / 矩阵 / 提示词」三个标签，默认打开模板，选好并载入后自动跳到矩阵；矩阵 tab 里可以改主题、轴名、轴简介、增删轴，模板和提示词不再弹窗，切过去就是整页工作区。只有当前 tab 挂载，切走时未保存的草稿会被丢弃。
- **页头控件**：右侧依次是**模型**下拉框（列出 DSH 能触达的所有 provider / model，包括本地 NInfer、Strata；每张矩阵记住自己的模型，选「跟随默认模型」就回到 DSH 的默认选择）、**并发**下拉框（0 = 一次过，或 1/2/3/4/6/8/12）、**保存模板**按钮、**刷新**和 ⋯ 菜单（导出 Markdown、「批量生成…」弹窗，弹窗里同样可勾选是否只生成空格，默认勾选）。
- **主题在左上角**：网格左上格显示这张矩阵的主题，点它就地编辑（Enter / 失焦保存，Esc 取消）。主题下面有「包含已生成格子」勾选框和整张矩阵的「全生成」按钮：实心品牌色，默认只补空格；勾上后按钮变成「全部重生成」，重做所有格子并覆盖已有内容。批量运行时同一按钮变成「生成中 x/y · 停止」。
- **每轴自带生成按钮**：每个行/列表头上都有「▷ 生成」和「全」勾选框；默认只生成这条轴上的空单元格，勾上「全」则整轴重生成。旁边「×」两下确认即可删轴（最少保留 1 行 1 列）。
- **格数随时可改**：表头右侧「+ 添加横轴」、表格底部「+ 添加纵轴」直接加；删减任意行/列后矩阵立即变成新尺寸，最小支持 1×1。
- **提示词可自定义**：「提示词」标签里分别编辑**系统提示词**和**用户消息**两段模板，**打开即显示当前生效的模板全文**（没改过就是内置默认）。两段都可写 `{纵标题}`、`{横标题}`、`{主题}` 等占位符，调用模型前按当前单元格替换；右侧列出全部占位符、含义和示例值，并实时预览实际发送的 system / user 两条消息。不动它直接保存 = 继续跟随内置默认。两段提示词都随矩阵保存，也会跟着模板一起存取。
- **模板**：内置 7 套——身边的小创意、未来研判、格栅理论、故事创作、人生规划、易经卦象、禅宗道理；每套都带说明和用法，**每套各带一句自己的生成提示词**（统一句式「……直接写这一段，不要开场白。」，载入模板即换上）。
- **模板用提示词生成 / 改写**：「模板」标签里有「载入模板 / 用提示词生成」两个子页签。「用提示词生成」一句话描述想要的矩阵，模型产出草稿（两轴 + 主题 + 提示词），确认后保存为预设；「我的」预设的详情页有「用提示词修改」，写下要改什么即原位改写该文件。Agent 侧对应 `creative_matrix(action:'template', idea, save?, file?, refineFile?)`。
- **保存模板**：页头「保存模板」把当前纵轴/横轴/主题/提示词写成 `presets/*.md`；对话框可选**覆盖当前模板**（仅用户模板）或**另存为新模板**。文件是普通 Markdown，可以手改、可以 git 管理。模板只存标题、轴和提示词，不存生成出来的格子。
- **删除模板**：模板标签选中自己的模板后，详情里有一个红色「删除模板」按钮：第一次点变成「确认删除」，第二次才删。内置模板只读，按钮禁用并说明原因。删除只删 `presets/*.md`，不影响当前矩阵和已生成的格子；如果删的是当前绑定模板，会同时解除绑定。
- **批量生成**：表格左上角「全生成」跑完整张矩阵；单行/单列用每轴自己的生成按钮。所有批量按钮默认只补空格，勾上「包含已生成格子 / 全」才重做已有内容。默认一次过（全部并行），页头「并发」可改成 1/2/3/4/6/8/12，可随时停止，矩阵上方有进度与失败计数。
- **单元格**：把纵轴当作因果律，推演它在横轴场景里必然产生的非线性后果；结尾带一条「什么情况下会失效」。
- **深度审阅**：草稿完成后再跑一轮独立红队，追加「独立红队审阅」。
- **Agent 工具**：`creative_matrix`，可在任意会话里读取矩阵、生成/写入单元格、切换模型。
- **自动保存**：每次生成/编辑都写回 `data/matrix.json`；写盘失败时矩阵上方会出现未持久化提示。

数据默认写到：

```
<baseDir>/data/matrix.json       # 当前矩阵与生成结果
<baseDir>/presets/*.md           # 用户保存的轴预设
```

`baseDir` 默认是 patch 里的 `polymath_matrix` 工作区。矩阵文件是普通 JSON，可直接看、可 git 管理、可被 Agent 的 fs 工具读取。`reset` 会把旧文件改名为 `matrix.json.bak-<ts>`，不会静默删除。

## 数据模型

```jsonc
{
  "version": 1,
  "title": "格致矩阵",
  "theme": "体现身边事物的组合变化。",
  "prompt": "结合纵横轴，用少于 150 字说清这个模型在这个场景里逼出了什么。",   // 空字符串 = 跟随内置默认系统提示词
  "userPrompt": "纵轴（模型）：{纵标题}（{纵提示}）\n横轴（场景）：{横标题}（{横提示}）\n主题：{主题}", // 空 = 内置默认用户消息模板
  "model": { "provider": "strata", "model": "qwen3.8-flash-next-iq3_s" },  // 可为 null = 跟随默认
  "preset": { "file": "gezhimatrix.md", "title": "格致矩阵", "source": "user" },  // 绑定的模板；null = 未绑定
  "rows": [{ "id": "r-ab12cd34", "name": "苹果", "hint": "一种普通水果……" }],
  "cols": [{ "id": "c-ef56gh78", "name": "早餐桌", "hint": "每天早上都会发生的小场景" }],
  "cells": {
    "r-ab12cd34:c-ef56gh78": {
      "markdown": "纯阳之象，象征天道刚健、自强不息；放到资源少的局面里，先立方向再补执行。",
      "takeaway": "纯阳之象，象征天道刚健、自强不息；",   // 取正文首句，落在标点处截断
      "mode": "fast",              // fast | deep | manual
      "hint": "",
      "model": { "provider": "deepseek-official", "model": "deepseek-flash" },
      "usage": { "inputTokens": 1200, "outputTokens": 900 },
      "edited": false,
      "updatedAt": 1760000000000
    }
  },
  "updatedAt": 1760000000000
}
```

限制：行/列各 1–12；name ≤ 80 字符、hint ≤ 300、theme ≤ 500、prompt / userPrompt ≤ 4000；单 cell markdown ≤ 200 KB；文件 ≤ 8 MB；同轴名称不得重复。读取时会归一化，指向不存在轴的 cell 会被丢弃并在 `warning` 里报告。

写盘是 `tmp + rename`，同一运行时内串行；外部修改文件后，下一次 `state` 会按 mtime 重载。

## 模板与预设

内置模板在 `templates/`，用户预设写到 `presets/`。两者都是 Markdown + 一小段 frontmatter：

```md
---
title: 身边的小创意
description: 身边事物 × 日常场景，练习把两个普通概念撞出新点子。
theme: 体现身边事物的组合变化。
prompt: |
  用身边的东西想出不寻常的点子，每个想法都要能说出为什么。直接写这一段，不要开场白。
rows:
  - name: 苹果
    hint: 一种普通水果，能看、能吃、会变色、会腐烂
  - name: 水
    hint: 会流动、会结冰、会蒸发，也会把东西泡软
cols:
  - name: 早餐桌
    hint: 每天早上都会发生的小场景，时间很紧
  - name: 下雨天
    hint: 计划被打乱，但也能玩出新花样
---

# 怎么用

先挑一个普通东西，再挑一个普通场景……
```

- **模板存什么**：标题、说明、主题、纵横轴的标题（含 hint）、**系统提示词**、**用户消息模板**；**不存任何已生成的格子内容**。
- `prompt` 写**一行一句话**，就是生成时给模型的 system 提示词；不写则用内置默认那句。可以带 `{纵标题}`、`{主题}` 等占位符（见「生成提示词」一节），保存的仍是模板。多行也能读，但一句话更好用——长度就靠这句里写的字数控制。7 套内置模板统一用「……直接写这一段，不要开场白。」这个句式。
- `userPrompt` 写用户消息模板（也支持占位符，通常多行）；不写则用内置默认。一行里的占位符全为空时整行省略，空的「（）」会被去掉。
- 内置模板只读；「保存模板」只会写 `presets/`，或覆盖你自己的用户模板。
- 载入模板会用模板的 rows/cols/theme/prompt/userPrompt 替换当前矩阵；旧 cell 会随旧轴一起被替换，面板会二次确认并显示会删多少格。
- **保存模板**：页头「保存模板」→「覆盖当前模板」（仅当矩阵来自用户模板）或「另存为新模板」。写入当前 theme、rows/cols、两段提示词；说明和正文可以一起编辑。新建重名时自动加 `-2`、`-3`，不会静默覆盖。
- **删除模板**：模板标签 → 选中自己的模板 → 详情里红色「删除模板」→ 再点「确认删除」。只删 `presets/*.md`，当前矩阵与格子不变；若删的是当前绑定模板，`data/matrix.json` 里的 `preset` 会清空，页头回到「未绑定模板」。内置模板只读，删除按钮禁用。
- `data/matrix.json` 会记下 `preset: {file,title,source}`，所以重新打开面板后仍然知道「覆盖」该写哪个文件。
- 文件里的 `description`、两段提示词和正文都会显示在模板详情页。

### 用提示词生成与修改模板

不想手写 frontmatter 时，让模型来写：

- **新建**：模板标签 →「用提示词生成」子页签 → 描述想要的矩阵（主题、两轴、风格）→「起草」。模型返回一份草稿（标题、说明、主题、纵横轴各 4–8 项、一句生成提示词），下方列出预览；满意按「保存为预设」写入 `presets/`，之后和其它模板一样可载入。
- **修改**：在「我的」里选中一个用户预设 → 详情里的「用提示词修改」→ 写下要改什么（如「横轴换成远程办公场景」「语气再狠一点」）→「起草」即原位改写该文件。正文说明和文件名保持不变；模型漏写的字段回落到当前矩阵或现有值，不会把自定义提示词悄悄降级。
- **内置模板只读**：想改内置模板，先载入，再用页头「保存模板 → 另存为新模板」存成自己的预设，然后用提示词改它。
- 起草/改写用的是这张矩阵当前生效的模型（面板可切换），一次调用约 1600 token 输出预算。

对应 API：`presets.draft`（`{idea}` → `{draft,model,raw}`）、`presets.refine`（`{id,idea}` → 写回原文件并返回新 `preset`）。

内置模板：

| 文件 | 用途 |
|---|---|
| `starter-simple.md` | 日常概念入门：苹果、水、影子 × 早餐桌、下雨天……（6 行 × 5 列） |
| `future-forecast.md` | 未来研判：情景规划、信号与噪声、二阶后果（6×5） |
| `latticework.md` | 格栅理论：复利、概率、激励、进化、机会成本、工程冗余（6×6） |
| `story-craft.md` | 故事创作：三幕、英雄之旅、冰山、契诃夫之枪（6×6） |
| `life-planning.md` | 人生规划：决策树、机会成本、反脆弱、生命历程（6×6） |
| `iching.md` | 易经卦象：八卦纵横相叠成六十四卦，思维工具，不做占卜承诺（8×8） |
| `zen.md` | 禅宗道理：无常、无我、不立文字、平常心（6×6） |

## 生成提示词

每个单元格可以改两段提示词：**系统提示词**（通常一句话）和**用户消息模板**（通常多行）。两个编辑框里存的是**模板**，不是最终文本：占位符会在每次调用模型前，用当前单元格的内容替换。

| 占位符 | 别名 | 代表 |
|---|---|---|
| `{纵标题}` | `{row}` | 纵轴标题（思维模型名） |
| `{纵提示}` | `{rowHint}` | 纵轴 hint |
| `{横标题}` | `{col}` | 横轴标题（场景名） |
| `{横提示}` | `{colHint}` | 横轴 hint |
| `{主题}` | `{theme}` | 这张矩阵的全局主题 |
| `{模板名}` | `{title}` | 矩阵标题（来自模板或默认标题） |
| `{补充要求}` | `{hint}` | 本次生成的额外要求（单元格抽屉里的 hint；批量生成时为空） |
| `{上一版}` | `{previous}` | 这个格子上一版的一句话结论 |
| `{坐标}` | `{cell}` | `纵标题 × 横标题` |

规则：

- 中文占位符精确匹配；ASCII 别名不区分大小写（`{ROW}` 等价于 `{row}`）。
- 不认识的 `{…}` **原样保留**，避免误伤 JSON、LaTeX 等普通花括号；值为空时替换成空字符串。
- 用户消息模板按行处理：一行里的占位符**全为空**时整行省略，空的「（）」也会去掉。这样 `主题：{主题}` 在没主题时不会留下一个空标签。
- 替换只发生在发送前；`data/matrix.json` 和 `presets/*.md` 里保存的始终是带占位符的模板，换一套轴仍然可用。
- 「提示词」标签右侧列出全部占位符，点一下插入到**最近编辑的框**（系统或用户），并显示它在预览单元格里的实际值；下方实时预览真正发送的 **system** 和 **user** 两条消息（子代理/聊天里「复制提示词」也走同一套替换）。
- 两段都遵循「打开就是当前生效的全文」：没有自定义时显示内置默认；不动它直接保存 = 继续跟随内置默认，不会把默认文本冻结成副本；「恢复内置默认」一键回填两段。
- 保存提示词会同时写入 `data/matrix.json` 的 `prompt` 和 `userPrompt`；之后所有生成（单格、每条轴的批量、Agent 工具）都用这两段。载入模板会把两段一起换掉；模板没有 `userPrompt` 则回到内置默认。
- 内置默认系统提示词只有一句：「结合纵横轴，用少于 150 字说清这个模型在这个场景里逼出了什么。」默认用户消息模板是「纵轴（模型）：{纵标题}（{纵提示}）/ 横轴（场景）：{横标题}（{横提示}）/ 主题：{主题} / 补充要求：{补充要求} / 上一版结论（不要重复）：{上一版} / 直接写这一段，不要开场白。」，空行会自动省略。

## 批量生成

每个行 / 列表头都有生成按钮，不再需要先在页头选轴：

- **表头「▷ 生成」**：默认生成该行（纵轴项目）或该列（横轴项目）上的所有空单元格；已经有内容的格子自动跳过。没有空单元格时不会静默重做，会提示勾选「全」。
- **表头「全」勾选框**：勾上后同一按钮变成「▷ 重生成」，整条轴上的所有格子都会重做并覆盖已有内容；不勾则只补空缺。
- **左上角「全生成」**：默认补齐整张矩阵的空格；按钮上方「包含已生成格子」勾选框勾上后，按钮变成「全部重生成」并重做整张矩阵，颜色也从品牌色变为警示色。
- **⋯ →「批量生成…」**：打开批量弹窗，默认勾选「只生成空单元格」；取消勾选才重写该范围内的已有内容。

批量开始后：

- **默认一次过**：一次批量里所有目标格同时开始生成；页头「并发」下拉框可选 1/2/3/4/6/8/12 限制同时进行的格数（0 = 一次过）。
- 每个 cell 完成就落盘并更新网格；并发值在批量开始时固定，运行中下拉框会禁用。
- 矩阵上方出现进度条、页头出现进度 chip，含并行格数、成功/失败/跳过计数；
- 可随时「停止批量」；停止会中止所有正在进行的格，已完成的保留；
- 批量中途刷新页面不会丢进度：`state.batch` 会继续报告，面板轮询恢复。
- 有格子失败不会中断整批，失败原因列在进度条下方，可单独重试。

对应 API：`batch.generate`（SSE 或 JSON 最终结果，可带 `concurrency`）、`batch.cancel`、`batch.clear`。SSE 事件是 `batch.start`、`cell.start`、`cell.done`、`cell.error`、`batch.done`。

## 轴的增删、改名与简介

- 点击表头标题 → 就地改名（Enter 保存、Esc 取消）。
- 点击标题下方的简介 → 就地编辑（Enter 保存、Esc 取消、失焦保存）；简介会进入系统提示词和用户消息模板的 `{纵提示}` / `{横提示}`，也会显示在模板详情里。
- 表格最右一列表头「+ 添加横轴」、最后一行「+ 添加纵轴」→ 输入名称后 Enter 直接加一条轴。
- 表头「×」→ 第一次点亮红色（「再按一次删除」），第二次才真正删轴，删轴会级联删除该轴上的单元格；每条轴至少保留 1 项，最小矩阵 1×1。
- 这些编辑都在「矩阵」tab 内完成，即时写回 `data/matrix.json`，不再需要单独的维度编辑页。

## HTTP API

前缀 `/creative-matrix/api`，同源（回环 + Origin/Host 一致）才可用。

| method | 说明 |
|---|---|
| `GET /creative-matrix/api` | 等同 `state` |
| `state` | 轴、主题、cell 摘要、生效模型、`selectedModel`、`concurrency`、`batch` 进度、`persisted`、`storePath`、`generating`、warning、`storeError` |
| `models.list` | 列出 DSH 可触达的 provider 与模型；`{refresh:true}` 绕过 60 s 缓存 |
| `model.set` | `{provider,model}` 写入矩阵模型；两个都留空 = 跟随默认 |
| `concurrency.set` | `{concurrency}` 设置同时生成的格数；`0` = 一次过（不限） |
| `cell.read` / `cell.write` / `cell.clear` | 单元格读写/清空 |
| `cell.generate` | 生成；`Accept: text/event-stream` 时走 SSE，否则等 JSON 最终结果 |
| `cell.cancel` | 中止该 cell 的生成 |
| `batch.generate` | 批量生成；`{scope:'all'|'row'|'col', rowId?, colId?, onlyEmpty?, mode?, concurrency?}`；SSE 或 JSON |
| `batch.cancel` | 停止正在运行的批量（中止所有正在生成的格） |
| `batch.clear` | 收起已完成的批量摘要 |
| `axes.replace` | 整体替换轴（表头「×」删轴、主题保存）：删轴级联删 cell |
| `axes.upsert` | 只增改、不删除（Agent 工具与表头「+ 添加轴」）：按 id 或名称匹配 |
| `axes.update` | 表头内联编辑：`{axis:'row'|'col', id, name?, hint?}`，只传要改的字段 |
| `prompt.set` | `{prompt,userPrompt}` 写入本矩阵的系统提示词和用户消息模板；省略某字段则保留原值，空字符串 = 内置默认 |
| `prompt.default` | 返回当前语言的 `{system,user}` 两段内置默认模板 |
| `presets.list` / `presets.read` | 列出/读取内置模板与用户预设 |
| `presets.save` | 保存当前 theme/rows/cols/prompt/userPrompt 为 `presets/<title>.md`；可带 `file` + `overwrite:true` 覆盖用户模板，`bind:true` 把矩阵绑定到该模板 |
| `presets.draft` | 用提示词起草模板：`{idea}` → `{draft,model,raw}`，不落盘 |
| `presets.refine` | 用提示词改写用户预设：`{id,idea}`，写回原文件；内置模板返回 `BUILTIN_PRESET` |
| `presets.delete` | 删除用户预设 |
| `presets.apply` | 把模板应用到当前矩阵，返回 `removedCells` |
| `prompt.preview` | 预览某格最终发送的两条消息：`{rowId,colId,hint?,custom?,userCustom?}` → `{template,userTemplate,system,user,vars}`；两个 `custom` 分别预览尚未保存的系统 / 用户草稿 |
| `export.markdown` | 拼整张矩阵为 Markdown |
| `reload` | 强制重读文件 |
| `reset` | 把现有文件改名为 `.bak-<ts>` 后重建示例矩阵 |

请求体：`{"method":"cell.generate","args":{...}}`；成功 `{"ok":true,"value":...}`，失败 `{"ok":false,"error":"...","code":"..."}`。

SSE 事件：

```
event: meta    data: {"provider":"…","model":"…"}
event: stage   data: {"stage":"draft"|"critique"}
event: delta   data: {"text":"…"}
event: done    data: {"key":"r-…:c-…","cell":{…},"persisted":true}
event: error   data: {"code":"…","message":"…"}
```

单飞：同一 cell 再点生成会 abort 旧请求（latest wins）。手动请求受 `concurrency.set` 的上限约束，默认 0 = 不限；超出上限的请求排队，30 s 仍未轮到返回 `429`。批量生成自带并发池，运行中不会被单格请求挤出队列。客户端断开不会中止生成，完成后照常落盘；页面刷新后 `state.generating` 仍能看到。

## Agent 工具

```
creative_matrix(
  action: 'state' | 'read' | 'generate' | 'write' | 'clear' | 'axes' | 'model' | 'template',
  rowId?, colId?, hint?, mode?: 'fast'|'deep',
  markdown?, theme?, prompt?, userPrompt?, rows?: [{id?,name,hint?}], cols?: [{id?,name,hint?}],
  provider?, model?, idea?, save?, file?, refineFile?
)
```

- `state` 返回轴 id/名称/提示、主题、两段提示词状态、cell 摘要与生效模型；不返回全文。
- `read` 返回单个 cell 全文（>8000 字符截断）。
- `generate` 与面板共用同一运行时，默认保存。
- `axes` 只增改，不删除；可顺带写 `prompt`（系统提示词）与 `userPrompt`（用户消息模板），删除轴只能在面板里做。
- `model` 切换这张矩阵的模型；`provider` 与 `model` 一起留空则跟随默认。
- `template` 用提示词起草模板：`idea` 必填，返回草稿（不落盘）；`save: true` 直接存成 `presets/*.md`（可用 `file` 指定文件名）；`refineFile` 点名改写某个用户预设并写回该文件。

## 配置

```yaml
- insert:
    - id: creative-matrix
      name: '@local/creative-matrix'
      config:
        baseDir: 'C:\Users\zgw31\Documents\deepseek-harness\polymath_matrix'
        maxTokens: 500         # 一格约 150 字，500 只是余量，不是长度控制器
        critiqueMaxTokens: 200
        temperature: 0.85
        outputLanguage: zh      # zh | en
        concurrency: 0          # 0 = 一次过（全部同时生成）；也可填 1–32
```

`cordis.patch.yml` 里实际只配了上面六项。运行时还支持这些可选项（不写就用默认值）：

| 配置 | 默认 | 说明 |
|---|---|---|
| `reasoningEffort` | `''` | `''` = 模型支持的最低推理档；`'selection'` = 沿用默认选择；也可写具体 id |
| `storePath` | `data/matrix.json` | 相对 `baseDir` 或绝对路径 |
| `presetsDir` | `presets` | 相对 `baseDir` 或绝对路径 |
| `provider` / `model` | 空 | 覆盖默认模型（面板选择优先于这里） |
| `timeoutMs` | 180000 | 单次模型调用超时 |
| `queueTimeoutMs` | 30000 | 排队请求的等待上限，超时返回 429 |

`concurrency` 只是启动值；面板顶部的「并发」下拉框可以在运行时改（`concurrency.set`），改完立即生效于下一批，Host 重启后回到配置值。

模型解析顺序：`config.provider` + `config.model` → 矩阵里保存的 `model` → `ctx.agentDefaultModel.currentSelection()`。都没有时面板显示 `NO_MODEL`，不会自动挑一个模型。

推理档默认取「模型支持的最低档」：创意推演需要把输出预算留给正文，而不是让推理过程吃掉全部 token。需要更深思考时把 `reasoningEffort` 设成 `'selection'` 或具体的 effort id，并相应提高 `maxTokens`。

## 设计说明

- **UI 与数据分层**：`client.js` 只留 store、SSE、Host API 动作和槽位注册；`client.ui.js` 是懒加载的 React 半边，只管组件、Markdown 渲染和 CSS。两者之间只有一个 `deps` facade（状态读取 + 动作 + 面板挂载生命周期），UI 不直接碰 `fetch` 或 store 内部。后续 UI 重排只改 `client.ui.js`。
- **三 tab 工作区**：模板 / 矩阵 / 提示词各占一个 tab，默认打开模板；只有当前 tab 挂载，切走时未保存的草稿会被丢弃。矩阵 tab 里的主题、轴名、轴简介、增删轴都是即时保存，没有「应用」这一步。模型与并发选择放在页头右侧（不再藏在网格下方），因为它们属于整张矩阵的全局设置。
- **矩阵编辑与模板写盘分开**：表头编辑（改名、简介、增删轴）、主题、两段提示词都只写 `data/matrix.json`；只有「保存模板」会写 `presets/`，避免每改一个字就产生一个模板文件。
- **主面板而不是聊天内联**：网格要横向空间，生成不应污染会话。
- **系统提示词就是一句话**：默认只有「结合纵横轴，用少于 150 字说清这个模型在这个场景里逼出了什么。」一句。试过用 6 条硬规则 + 示例来控格式，结果每格稳定输出 2000 字、五个小标题；换成一句话并把字数写进句子里，同样是这个模型，稳定落在 90–150 字。想改就在面板里改，随矩阵与模板保存，不用改代码。
- **用户消息也可编辑，但默认结构不变**：默认用户模板复刻了原来手写的「纵轴 / 横轴 / 主题 / 补充要求 / 上一版 / 直接写」结构；空值行省略、空括号去掉，所以默认输出与旧版一致。想加字段就在用户模板里加，不用改代码。
- **提示词是模板，替换在发送前**：两个编辑框和 `presets/*.md` 里保存的都是带占位符的原文；`lib/prompt.js` 在每次生成、批量、复制提示词和面板预览时，用同一套 `promptVars` / `renderPrompt` 按当前格替换。未知的 `{…}` 原样保留，避免误伤 JSON/LaTeX；面板只展示 Host 返回的 `vars`，不另写一套替换逻辑。
- **批量作用域默认只补空缺**：左上角与每轴的勾选框默认不勾，等于「只补空缺」；勾上才重生成该作用域并覆盖已有内容。没有空格的轴会明确提示勾选「全」，不再靠「再按一次」的隐藏状态触发覆盖。
- **Markdown 而不是 JSON**：SSE 流式自然，避免 JSON 修复重试；格子标签（takeaway）取正文首句，超长时在标点处截断而不是硬切 60 字。旧格式的 `> 一句话：` 行仍然优先识别。
- **Host 侧生成**：面板和 Agent 工具共用 `lib/core.js`，两种调用不会各写一套逻辑。
- **模板是 Markdown 文件**：人可读、可手改、可版本管理；内置与用户预设用同一套解析器。
- **不做 iframe**：直接在主面板里渲染 React，继承主题 token 与 locale。
- **安全渲染**：自写 Markdown 子集，全部是 React 文本节点，不用 `dangerouslySetInnerHTML`。
